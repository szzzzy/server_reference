# 网络服务器改造方案 v3(按固件实际协议 · 虚拟测试服务器)

> **需求基线(已全部确认)**:
> 1. **固件通信协议已定稿**(见"固件协议基线文档"):MQTT + HTTPS + WSS 三链路,服务器按该文档 §6 实现虚拟测试端;
> 2. **无固定 IP**:固件走 `CONFIG_JULIA_SERVER_ADDR`(域名,一处配置派生 MQTT/WSS/OTA 白名单)✅ 已内建;
> 3. **证书已备**:`certs/` 工具包(CA/服务器/板卡证书)✅;
> 4. **语音音频只在 WSS 走**,MQTT 是纯控制面——与 v2 假设不同,本节已按实际协议重写。
>
> 固件协议基线文档(外部):`julia-esp32s3-ai-terminal-fused` 融合工程 + `native_ota_example`。本文档是**服务器虚拟测试端**的实现依据与清单。

---

## 0. 结论摘要

1. **服务器 = 三个服务,部署在同一台机器(本地先 5090/本机,验收切客户服务器)**:
   - **MQTT 控制面**:OTA 检查/通知/状态、音频素材检查/状态、语音命令 `vcmd`/`vstatus`(文本);
   - **HTTPS 文件服务**:固件 bin + 音频素材下载(支持 `Range`/`ETag`,SHA-256 与清单一致);
   - **WSS 语音服务**:双向实时语音(`/voice`,Bearer 鉴权)——**这是语音主链路**,协议与现有串口版同构,PCM1 帧格式一字不差。
2. **流水线网关 + 会话中心(v2 设计)依然适用**,但适配器职责按实际协议收敛:MqttAdapter=控制面、HttpsAdapter=文件、WssAdapter=语音 + FILE_SEND。
3. **推理层零改动**:WSS 收到的 PCM1 帧直接进现有 `read_frame`/VAD/ASR/Qwen3/CosyVoice2;下行 `SPKS`+二进 PCM。
4. 身份:`device_id`(`esp-<MAC>`)= board_id;WSS 鉴权 = `Authorization: Bearer <token>`;MQTT 可选无/账号/密码/token/mTLS。
5. 证书:本地虚拟测试用 `certs/` 已生成的自签 CA;**注意**:固件 MQTT TLS 用系统证书捆绑,自签 CA 需固件团队把 `ca.crt` 并入信任(或测试期走 TLS 白名单直连),这是 M3 联调前需要双方确认的项。

## 1. 固件协议要点(服务器必须遵守)

### 1.1 公共约定

| 项 | 值 |
|---|---|
| `device_id` | `esp-` + 芯片基础 MAC 6 字节小写 hex(如 `esp-30c6f7a1b2c3`),稳定不变 |
| 服务器入口 | `CONFIG_JULIA_SERVER_ADDR`(域名,派生 MQTT/WSS/OTA 白名单) |
| MQTT | `mqtt://<addr>:1883`(TLS + 系统证书);keepalive 60 s / 重连 10 s |
| WSS | `wss://<addr>:9443/voice`;Bearer token;15 s PING/10 s PONG 超时/5 s 重连;单帧 ≤1200 B |
| JSON 上限 | 响应 ≤1024 B;检查请求 ≤512 B |
| 时间戳 | Unix 秒;`expires_at` 须在未来(设备未同步时间时跳过比较) |

### 1.2 Topic 一览(服务器订阅/发布)

| 方向 | Topic | 说明 |
|---|---|---|
| 设备→服务器 | `/device/ota/check` | QoS1 非 retained,版本检查 |
| 服务器→设备 | `/device/ota/response/<device_id>`、`/device/ota/notify/<device_id>` | QoS1,critical(设备订阅) |
| 设备→服务器 | `/device/ota/status/<device_id>` | QoS1 持久化事件 + downloading 进度 |
| 设备→服务器 | `/device/audio/check`(推断命名,固件侧尚未接线) | 音频素材检查 |
| 服务器→设备 | `/device/audio/response/<device_id>`(推断命名) | 音频素材响应 |
| 设备→服务器 | `/device/audio/status/<device_id>`(推断命名,§3.4 Kconfig) | 音频状态(非持久化) |
| 服务器→设备 | `voice/esp32s3/vcmd` | QoS1,纯文本语音命令 |
| 设备→服务器 | `voice/esp32s3/vstatus` | QoS1,纯文本回执 |

### 1.3 服务器响应必须满足的校验规则(防呆清单)

**OTA(§2.3)**:`type=ota_check_response`(兼容旧值 `ota`);`update` 布尔必填;`request_id/device_id/product/hardware_version` **原样回显**;`update=false` 合法;`update=true` 时必填 `artifact_id(≤95)`、`version(x.y.z 纯数字且高于当前版本,除非 force_update)`、`url(https://,主机精确命中白名单=JULIA_SERVER_ADDR)`、`sha256(恰 64 hex)`、`image_size(uint32>0)`、`security_version(≥0)`、`expires_at(未来)`;`force_update` 可选布尔;**同 artifact_id 曾被隔离(QUARANTINED)必须拒绝**。

**Audio(§3.2)**:`type=audio_check_response`(无旧别名);`update/request_id/device_id/product` 回显;`update=true` 必填 `audio_id(≤95)`、`version(≤31,不做数值比较)`、`url(https://,白名单宽松:为空直接放行)`、`sha256(64hex)`、`file_size(>0 且 ≤4 MiB)`、`expires_at`;无 force_update/security_version/job_id。

**OTA 状态事件(§2.5)**:`state ∈ {accepted, downloading, verifying, rebooting, booted_pending_verify, succeeded, failed, rolled_back, deferred}`;`error_code` 为字符串枚举(17 种);`event_id`(32hex)幂等,服务器按 event_id 去重;`downloading` 进度按最新覆盖。

**Audio 状态(§3.3)**:`state ∈ {accepted, downloading, verifying, ready, failed}`;`progress 0-100`;`error_code` 为**数值**枚举(0-16);无幂等,按状态覆盖;OTA 运行中音频下载互斥(OTA 优先,服务器不应主动给正在 OTA 的设备发音频更新)。

### 1.4 下行语音命令(WSS 文本 / vcmd 同一套)

`FILE_SEND <uri>` | `MIC_START` | `MIC_STOP` | `MICS <bg>`(-10000~0)| `MICW` | `SPKS <rate>` | `SPKV <0-100>` | `SPKE` | `SPKT`(三音自检)

**下行 PCM**:mono PCM16 二进制帧(偶数长度,≤1200 B/帧);**必须先 `SPKS` 再发 PCM**,否则设备丢弃。

### 1.5 文件推送(FILE_SEND,设备→服务器)

`BEGIN FILE <size> <name>`(文本)→ 二进制帧×N(≤1200 B)→ `END <bytes>`;失败 `ERROR bad_uri/bad_extension/file_open_failed/sd_busy/file_size_failed/file_name_too_long`;仅 `.wav`,≤8 MiB,URI `SD:/x/y`→`/sdcard/x/y`、`SPIFFS:/x/y`→`/spiffs/x/y`;中途失败断连,绝不发截断 END。

## 2. 服务器架构(按固件协议收敛)

```
  设备(esp-<MAC>)
   ├─ MQTT  控制面 ── broker(1883/8883 TLS)
   ├─ HTTPS 文件   ── <url>(Range/ETag/SHA-256)
   └─ WSS   语音   ── wss://:9443/voice(Bearer)
                        │
        ┌───────────────┼──────────────────────────┐
   MqttAdapter(控制面)  HttpsAdapter(文件)      WssAdapter(语音+FILE_SEND)
        │ OTA状态/音频状态/vstatus     │ 固件bin/素材文件       │ PCM1帧/文本命令
        └────────────────┬────────────┴─────────────────┬────┘
             统一会话中心 Session Hub(键=device_id)          │
                          │                              │
                     控制面状态/命令                流水线网关(语音状态机)
                                                VAD→FunASR→Qwen3→CosyVoice2
```

- **会话中心**:注册/去重(ota_status event_id)/生命周期;设备身份=device_id;IP 仅作日志与同 IP 限速(设备走平台,IP 不可靠,不作身份)。
- **推理层完全复用**:WSS 的 PCM1 帧字节流与串口版同构,直接对接现有 `board_serial_asr_test.read_frame` 与 `capture_until_endpoint`;下行 TTS 转成 `SPKS`+二进制帧。
- **命令映射**:`MICS/MICW/MIC_START/MIC_STOP/SPKS/SPKV/SPKE/SPKT` 与现有串口命令语义一一对应(SPKT 为新增:本地三音自检,服务器可直接透传)。

## 3. 虚拟测试服务器最小实现清单(= 固件文档 §6)

### 3.1 MQTT 端(本地自建 broker;验收连客户平台)

- **broker 决策:本地自建**(Python `amqtt`,与虚拟服务器同机同进程启动;1883 明文测试,8883 TLS 用 `certs/` 证书备选);验收时改为连客户平台 broker(地址/凭证换配置);
1. 订阅 4 个上行 topic:ota/check、ota/status/+、audio/status/+、vstatus;
2. `ota_check` → 校验/回显 → 回发 `ota_check_response`(无更新/有更新两分支,清单来自本地 `releases/manifest.json`);
3. `audio_check` → 回发 `audio_check_response`;
4. 可选:发 `ota_notify` 触发立即检查;向 `vcmd` 发命令做语音链路验证;
5. `ota_status`/`audio_status`/`vstatus` → 记录(`event_id` 去重)、进度覆盖、CSV/日志落盘。

### 3.2 HTTPS 文件端

- 固件:`GET <url>` → `200` + `Content-Length == image_size`;`Range: bytes=n-` → `206` + `Content-Range`;`ETag` 同文件恒定(变化→设备从零重下,只允许一次 200 回退);
- 音频:同机制,`file_size == 实际长度` 且 ≤4 MiB;
- SHA-256 必须与清单一致(设备回读校验,不匹配→ `HASH_MISMATCH`)。

### 3.3 WSS 端

- `wss://:9443/voice`,校验 `Authorization: Bearer <token>`;
- 上行解析:656 B binary → PCM1(seq/dBFS/校验和);`BEGIN FILE…`→收集→`END`(字节数一致);`ERROR *` 记录;
- 下行:文本命令表 + binary PCM16(先 `SPKS 24000`)。

### 3.4 验证时序(全链路)

```
ota_check → ota_check_response(update:true) → ota_status(accepted) → GET 200/206 →
ota_status(downloading×N) → verifying → rebooting → booted_pending_verify → succeeded
audio_check → audio_check_response → audio_status(accepted/downloading/verifying/ready)
WSS: 连接(Bearer) → MIC_START/MICS → PCM1 帧↑ → SPKS+SPKE+PCM↓ → vstatus 回执
```

## 4. 证书与安全

- 现成:`certs/` 自签 CA + 服务器证书(SAN 含本机 IP/可加域名)+ 板卡/设备证书;
- 虚拟测试:WSS 用自签证书即可(固件 trust 需确认,见 §0.5);MQTT 可用 TLS(8883)或明文本地测试,视固件配置;
- 验收:客户域名证书替换 `server/` 两张;设备鉴权建议 token(Bearer)起步,mTLS 为增强项;
- `.gitignore` 已排除全部私钥与 `certs/` 生成目录。

## 5. 服务器端实施清单(阶段一)

| # | 模块 | 说明 |
|---|---|---|
| 1 | `session_hub.py` | 会话中心:设备注册/去重/生命周期/日志 |
| 2 | `mqtt_adapter.py` | paho-mqtt 客户端:订阅 4 主题、OTA/audio 应答逻辑、状态落盘 |
| 3 | `https_file_server.py` | Range/ETag/SHA-256 文件服务(FastAPI 或内置 handler) |
| 4 | `wss_adapter.py` | WSS 语音服务(Bearer、PCM1 解析、命令、FILE_SEND 接收) |
| 5 | `voice_bridge.py` | 语音桥:WSS PCM1 → 现有推理管线;TTS → SPKS+二进制帧(复用 voice_daemon) |
| 6 | `board_simulator.py` | 模拟设备:MQTT 检查/状态 + WSS 语音流 + 文件下载断言(留待与真机对照) |
| 7 | `config.json` 扩展 | `server_addr`/端口/token/证书/manifest 路径/设备列表 |
| 8 | `releases/manifest.json` | 发布清单(固件 + 音频)虚拟测试模板 |

**语音链路演进(先 stub 后真推理)**:
- **stub 模式(先做)**:WSS 收到 PCM1 帧只做解析/指标统计(帧率、seq 连续、dBFS、丢帧)+ 文本命令回执;不加载模型,秒级启动,专供协议链路验证;
- **真推理(后接)**:启用 `voice_bridge.py` 时,WSS 的 PCM1 帧直接喂现有 `read_frame`/`capture_until_endpoint`/ASR/Qwen3/TTS 管线(加载模型,复用 voice_daemon);
- `config.json → voice.mode: "stub" | "real"`,切换不改代码。

**启动方式**:单命令 `start_virtual_server.cmd` 同时拉起 broker + 三服务 + 可选模拟器;日志/状态落盘到 `runs/` 时间目录(与现有一致)。

**里程碑**:M0 资料回填(本文档 ✅)→ M1 三服务 + 模拟器自测(3-5 人日)→ M2 真机联调(固件就绪后)→ M3 验收切换(客户环境)。
