## 9. 会话结束约束收敛(2026-09-01 定稿)

**回待机(需重新唤醒)仅三条约束**,普通问答轮(question)之间保持唤醒态持续对话、无需重新唤醒:

| 约束 | 位置 |
|---|---|
| ① 600s 空闲超时 | `wk_timeout_s`(config `voice.real.wake.timeout_seconds=600`),主循环空闲超时检查 |
| ② 意图层轮次结束 | sleep/decline 收尾回话后回待机;no_reply 连续 ≥ `no_reply_tolerance_rounds`(默认3)轮 dismiss 回待机(前 N-1 轮按正常对话、第 N 轮确认,见 §20) |
| ③ 设备断联重连 | `on_client_disconnected` 立即回待机;`on_client_connected` 新连接从待机开始(需重新唤醒) |

`_noreply_streak`(连续敷衍疑似计数)随唤醒/断联/意图结束清零,跨会话不累计;
前 N-1 次仅计数并按正常对话处理(不空播报),连续第 N 次才确认敷衍(§20)。

## 10. 播放期打断升级 v2·接住(2026-09-01)

**背景**:旧设计"半双工丢弃 + 打断只停播"冲突 —— 回声判断已识别出人声,却又把插话音频整体丢弃,
功能只剩"提前停播"。现按"判断在云端、设备只采集"的原则合并:

| 变更 | 说明 |
|---|---|
| 判别线程保留插话文本 | `_InterruptDetector` 逐块标记"回声相似/人声"(块文本 vs 播文相似度),命中时 `hit_text` = 最后一个回声相似块之后的文本(v2 不再丢弃) |
| 打断接住直接作答 | 打断 → SPKE 停播 → 插话文本经 `_pending_interrupt_text` 由主循环**直接作答**(用户无需重说);答完再 MIC_START 续听 |
| 消费命中标志 | 所有打断出口(段内/循环顶/唤醒应答)消费后 `_interrupt_hit.clear()`,修复"残留命中杀死后续回答"的隐患 |
| 防死循环 | 连续"抢话-作答-再抢话"最多接住 `interrupt_max_burst`(默认3)轮,超限丢弃 |
| 行为兼容 | 无插话文本(异常/残留)保持旧行为(仅停播+MIC_START);唤醒/意图应答仅停播(不接住,见 §10 边界) |

抢话不接住(保持停播)。

## 11. MIC_START 编排修正(2026-09-01)

**设计**:唤醒应答后主动发 MIC_START(设备→LISTEN);**非唤醒"说"完成(问答/空轮/敷衍轮/
打断接住作答的 SPKE 之后)不主动续听** —— 设备回 IDLE,服务器在持续上传流上继续 VAD,
**检测到下一轮合法语音起始才发 MIC_START**(检测后再发,不再"说完立刻续听")。

| 变更 | 说明 |
|---|---|
| 新增 `_mic_started` 状态 | 会话级标志(wake/断联重置);True=设备在 LISTEN,False=等待下一轮语音起始 |
| `capture_until_endpoint` 新增 `on_start` 回调 | 检测到 speech_started 置位时调用一次(engine/board_serial_asr_test.py,默认 None 零影响) |
| `_on_speech_start`(主循环) | 唤醒态下"检测到合法语音起始 → 未在 LISTEN 才发 MIC_START";唤醒应答后首问不重复发 |
| `_answer_qa`/空轮/no_reply 尾部 | wake 模式下不再主动 MIC_START(`_mic_started=False`);`voice.mic_restart_after_answer` 仅旧模式生效 |
| 断联/空闲超时 | 同时复位 `_mic_started`;重连从待机开始不变 |

**依赖前提**:新版固件 WSS 认证后**持续上传** PCM1(IDLE 期间不断流),服务器才能自行检测语音起始。

## 12. 播放溢出修复(2026-09-01,ERROR playback_overflow)

**根因(代码定位)**:`_stream_tts_segment` 旧实现把每个 `chunk_N.pcm` **整块突发**推给设备
(≤1200B 循环内无间隔),随后才 `sleep(0.88×音频时长)` —— ① 突发灌入(整块一次性进设备
TCP/FIFO);② 0.88 系数 = **1.14×实时**持续累积。设备播放 FIFO 1~4s 内必然填满 →
上报 `ERROR playback_overflow`(17:42 运行:两次真实回答分别在 SPKS 后 0.86s / 4.08s 必现)。

| 修复 | 说明 |
|---|---|
| 问答段逐帧匀速 | `_stream_tts_segment`:每帧(≤1200B ≈25ms@24kHz)**逐帧 sleep = 帧时长 ×1.0**(≈1.0×实时),设备缓冲恒定不涨;前 6 帧(150ms)快速填充(0.012s/帧)给设备开播余量 |
| 唤醒/意图应答同样修复 | `_speak_prompt` 旧实现 `sleep(0.02)`=1.25×实时,同样会溢出 — 改为同节奏(1.0×+前 6 帧快填),保留逐帧打断检查 |
| 文档同步 | real_engine 模块注释/`_stream_tts_segment` docstring、README、算法链路说明 §8(0.88≈1.14×实时 表述全部更新) |

**兼容**:本地串口 V5 路径(`engine/realtime_pipeline.py::board_speaker_chunk`,0.88 系数)未改动
(不属云端 WSS 链路,如后续串口端也报溢出可同样处理)。

## 13. 段级噪声判决(2026-09-01,补充层)

**背景**:能量 VAD 无"人声"概念 —— 你确认"没说话"的 9.64s 段被判"开始说话"并连续触发
空播报轮;噪声把 bg 从 -60 拉到 -52 后真实人声起始延迟到 10s+;长段噪声还会被当"敷衍"
(no_reply ≤4 字)累计 → 3 轮误结束会话。按"不动前人调参、只补必要层"原则实现:

| 补充 | 说明 |
|---|---|
| `_judge_noise_segment` 判决器 | 判据 = 时长异常(≥8s 或无端点)+ 占空比 ≥0.9 + 识别文本 ≤4 字(空或短),三者全中 → 噪声;`voice.real.vad.noise_gate`(默认开,关=旧行为) |
| 噪声段动作 | 重锚 bg(10% 分位,复用 heal 修法)/ **不刷新 `_awake_at`**(噪声不算交互)/ 文本丢弃走空轮 / `audio/noise_*` 录音落盘 |
| no_reply 段长上界 | 段长 ≥ `no_reply_max_duration_s`(2s) 的"嗯嗯"不按敷衍处理(防 9.64s 噪声段 3 轮误 dismiss) |
| 观测 | 新增 `server/runs/<run>/voice_rounds_log.csv`:每轮 时长/占空比/端点/识别文本/判决(noise/empty/speech) |

**未动**(信任前同学参数):`capture_until_endpoint` 全部参数、`NoiseFloorTracker` 全部参数、
预卷回退规则。判据阈值走 config 可调。

**验证**(单元):9.64s 噪声+短文本 → noise ✓;3s 正常问句 → 保留 ✓;15s 无端点+空 → noise ✓;
15s 无端点+有字(混合轮)→ 保留 ✓;开关关闭 → 旧行为 ✓。

| 放行策略 | 模型缺失/加载失败/判段异常 → 按语音放行(宁可多轮不可漏话),纯能量行为不变 |

### §19 补充4(2026-09-02 16:0x:自问自答 —— 回声免疫失效)

**现象**(16:09 运行 CSV 实证):答案播放中,判别线程把**答案自身的回声残片**判为插话:
"从一数到十"→答"一、二…十"→ `interrupt_text="一二"`; "嗯"→答"有什么我可以帮你"→
`interrupt_text="有什么"`; "傻逼"→答"听起来你很烦躁…"→ `interrupt_text="听起"` → 连锁
接住作答(答回声)→ 新回声再命中 → **自问自答循环**。

**根因**:`_InterruptDetector` 用整串 `SequenceMatcher.ratio()` 比对,播放开头 300ms 块
只识别出**截断前缀**("一二" vs 20 字播文,ratio≈0.18<0.5)→ 假命中。回声残片是播放文本
的**子串**,整串比值永远相似度低 —— 回声免疫被算法形式破坏。

**修复**:`_echo_similarity(short, long)` = 匹配块长度和/较短长度(子串容忍):
- 回声残片("一二"/"听起"/"有什么"/"床前明月光疑是地")→ **1.00**(按回声,不打断);
- 真实插话("讲个故事"/"对不起"/"别烦我")→ **0.00**(正常打断);
- 边界:与播文仅共享 1 字(如"那天"含"天")→ 0.5 边缘,按回声处理(偏向免疫,
  真实抢话可由下一轮 VAD 捕获/重说)。
- 替换 hit 判定与逐块标记两处;`min_similarity` 配置不变。

## 17. WSS 保活结论(2026-09-02,固件侧确认)

固件侧结论(见 `wss_transport.c:1050/1071`):
- 设备 15s 无下行 → 发空载荷 PING;10s 内收到**任意合法下行帧(含 WS PONG)**
  → 复位空闲计时;**Python `websockets` 自动 PONG 足够维持连接,无需业务层保活**;
- 服务器主动 WS PING,设备也原样回 PONG;`SPKV` 不建议当保活(音量变量重写/日志/
  可能覆盖最新音量/无应用层回执);
- 未来如要检测"业务任务仍能处理命令",再新增 `HEARTBEAT <seq>/HEARTBEAT_ACK <seq>`
  (当前固件未实现)。

服务器侧动作:`wss.ping_interval=10 / ping_timeout=20`(**定位:服务器侧死连接检测**,
半开连接 ≤30s 清理,非设备保活);对既有"55s 空闲断联"的重新解读:PONG 满足设备计时

## 18. WSS 注压测试接口(2026-09-03,背压复现)

**背景**:固件侧定位"设备 TX 短暂背压(WANT_WRITE/EAGAIN)被当死连接销毁"后,
需要服务器侧能**主动制造背压**来验证新固件重试逻辑。

**实现**:暂停读取全部 WSS 上行 + 收紧 SO_RCVBUF(4096)→ TCP 窗口关闭 →
设备发送缓冲耗尽 → 设备侧 TLS write 复现 `WANT_WRITE/EAGAIN`。
注意:只睡 handler 无效(websockets 协议层会继续读 socket 并缓冲),
必须暂停底层 transport 读取(`wss_adapter._pause_ws`)。

**触发方式**(两种等价):
- 服务器控制台(stdin,需 `--tty`):输入 `wait 5` / `wait 50` / `wait 0`(取消);
- HTTP:`GET https://<服务器>:8443/__stall?sec=5`(返回 `{"ok":true,"stall_seconds":5}`)。

**日志**:开始/结束各一条(`WSS 注压开始/结束: ...`),`/__status` 增加
`wss.stall_remaining_s` 字段。

**使用建议**:
- 注压 5~15s:≤4s 可能被路径缓冲吸收不产生 WANT_WRITE;≥20s 会触发设备自身
  15s/10s 保活(PING 没人应),混淆被测行为;
- 新固件预期:短暂注压(≤固件重试上限+余量)不拆连接、seq 跳变但存活;
  长注压(≥固件兜底 2~3s)→ 固件兜底断联,日志仍是 1006 —— 属预期兜底路径;
- 自测:`server/test_stall_selftest.py`(隔离端口 19443/18443,不碰在跑服务);
  网络级背压证明:`server/probe_pause_reading.py`(raw TCP:暂停后发送端 256KB 处阻塞)。

## 20. no_reply 两级判定: 前 N-1 次按正常对话(2026-09-03)

**背景**:设计(90f584a)为"听到敷衍(嗯嗯/知道了…)后**不回复**"(空播报)。评审发现该
单次判定不可靠 —— 前两次"嗯嗯"很可能是**正常应和**(用户没观点要表达、对引导语的自然
回应),仅凭单次/两次无法断定是敷衍;立刻空播报会打断正常对话(用户感觉被无视)。
2026-09-03 改为**两级判定**:单次 no_reply 只标"疑似",需连续次数才确认。

| 轮次 | 旧行为(90f584a) | 新行为(2026-09-03) |
|---|---|---|
| 前 N-1 次(默认前 2 次) | 空播报(SPKS+0.12s 静音+SPKE),不回复 | **按正常对话处理**:照常计数/记录(NOREPLY 观测),落入 `_answer_qa` 正常回答(LLM 结合上下文);不空播报、不结束会话;计数**不重置** |
| 第 N 次(`no_reply_tolerance_rounds`,默认 3) | 确认敷衍 → dismiss 结束会话 | 同左(不变:无表达结束,dismiss 后不续听) |
| 间隔出现 question(非敷衍) | 打断连续计数(清零) | 同左(不变) |
| 长段"嗯嗯"防护(≥2s) | 转 question,不进计数 | 同左(不变) |

**实现**(`server/real_engine.py` 意图块):新增 `suspected_noreply` 标志;
`no_reply` 命中且 `_noreply_streak < _noreply_tolerance` → 置疑似,**落下方正常问答**
(不 continue、不空播报);question 分支的 `_noreply_streak = 0` 仅对非疑似轮生效。
`engine/intent.py` 仍只做分类(单测不变),确认逻辑在引擎侧(文档串已同步)。

**观测**:疑似轮照常记 `NOREPLY <text>`(last_texts 环形观测)与 `voice_rounds_log.csv`
