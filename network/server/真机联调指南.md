# 真机(固件端)联调指南:参数填写与操作

> 适用:ESP32-S3 固件(julia-esp32s3-ai-terminal-fused)对接本虚拟测试服务器。
> 前提:服务器与真机在**同一局域网**;双方防火墙/AP 隔离已关闭。

---

## 一、参数清单(固件端要填/配的值)

### 1.1 必填参数(不填连不上)

| # | 固件参数(Kconfig) | 填什么(本地测试) | 服务器侧对应 | 填错的表现 |
|---|---|---|---|---|
| 1 | `CONFIG_JULIA_SERVER_ADDR` | **以 `ipconfig` 当前出口 IP 为准**(示例 `172.16.72.60`(无线)/`192.168.137.1`(本机热点);证书已覆盖 7 地址:`.60/.1/.159/.2/.4/127/localhost`,切换后重跑 `make_test_artifacts.py --addr <当前IP>`) | `network/server/config.json → server.addr`(auto 自动) | 连接超时/重连;OTA URL 白名单拒绝 |
| 2 | `COMM_DEVICE_AUTH_TOKEN_VALUE`(或 `WSS_TOKEN`) | `julia-test-token-2026` | `config.json → wss.token` | WSS 握手被拒(4401) |
| 3 | `WSS_SERVER_PORT` / `WSS_PATH` | `9443` / `/voice` | `config.json → wss.port/path` | 端口连不上(每次 Firmware 必配) |
| 4 | `OTA_PRODUCT_ID` | `julia-ai-device` | `network/server/releases/manifest.json → device.product` | OTA 检查答 update=false |
| 5 | `OTA_HARDWARE_VERSION` | `1.0` | `manifest.json → device.hardware_version` | 同上 |
| 6 | `OTA_ALLOWED_URL_HOSTS` | 留空(自动回退 `JULIA_SERVER_ADDR`) | URL 主机名必须 = server.addr | OTA 下载 URL 被拒 |
| 7 | MQTT 地址 | `mqtt://<JULIA_SERVER_ADDR>:1883` | 服务器 broker 1883(明文) | MQTT 连不上 |
| 8 | 上行音频 | 16 kHz / 16 bit / 单声道 / 20 ms 帧 | 服务器读取端固定 | 识别错乱/无识别 |

### 1.2 按需参数

| 参数 | 建议 | 说明 |
|---|---|---|
| MQTT TLS | 本地测试**先关闭** | 固件用系统证书捆绑,无法信任自签 CA;开 TLS 需把 `certs/ca/ca.crt` 并入固件信任(固件团队操作) |
| 下行采样率 `SPKS <rate>` | 服务器现固定发 `24000` | **真机 I2S 必须支持 24000**;不支持则改 `config.json → voice.downlink_rate`(22050/48000 等)并确保固件一致 |
| 语音模式 | 一问一答(无唤醒词) | 服务器不会发唤醒相关命令;真机仅需实现 MIC 上传与下行播放 |

### 1.3 证书项(重要)

- **WSS 是 TLS**:真机校验证书时**主机名必须命中服务器证书 SAN**;
  - 服务器证书 SAN 现为:`localhost`、`172.16.61.159`、`172.16.72.60`(当前无线网段)、`192.168.137.1`(本机移动热点)、`172.20.10.2`、`172.20.10.4`(历史网段保留兼容)、`127.0.0.1`(再换网 → 重签);
  - `JULIA_SERVER_ADDR` 用 IP(推荐本地测试):必须命中上述 SAN 列表,否则重签:
    `certs\generate_certs.py server --ips <新IP>`(用 .venv_5090_llm 的 python);
  - 用域名:先 `generate_certs.py server --domain <域名>`,再让固件信任自签 CA;
- 固件侧要把 `certs/ca/ca.crt` 纳入信任(测试期可临时关闭主机名校验,联调后必须开启)。

## 二、服务器端操作(联调前检查,5 步)

1. **启动(real 模式,必须用 GPU 环境 python)**:
   ```
   .venv_5090_llm\Scripts\python.exe network\server\run_server.py --voice-mode real
   ```
2. **确认引擎就绪**:浏览器/curl 打开 `https://<当前IP>:8443/__status`,`engine.status=ready`(=模型加载完成,~20-30s);
3. **确认 manifest 与本机 IP 一致**:若改过机器/网络,重跑
   `make_test_artifacts.py --addr <当前地址>`(URL 主机名 = JULIA_SERVER_ADDR,否则 OTA 白名单拒);
4. **确认证书 SAN 覆盖地址**(见 1.3,IP 没变则已覆盖);
5. **确认端口可访问**:局域网内 `Test-NetConnection <当前IP> -Port 1883/8443/9443`(Windows 防火墙需放行,或临时关闭)。

## 三、真机操作步骤(联调流程)

| 步骤 | 操作 | 服务器端观察点 |
|---|---|---|
| 1 | 固件配置上述参数后**烧录** | — |
| 2 | 上电;固件自动连 MQTT + WSS(重连周期 5s) | 日志 `WSS 设备接入: <IP>`;`MQTT <- vstatus`(若有) |
| 3 | **本地唤醒词固件**:设备自触发开麦,无需服务器指令;无唤醒词固件:服务器终端发 `MIC_START`(`--tty` 手动输入) | 日志 `WSS 设备接入`;引擎 `last_texts` 出现"Q1: …"即开麦成功 |
| 4 | 对着真机说一句问题(如"现在几点") | 日志 `ASR` / 引擎 `last_texts` 出现"Q1: …" |
| 5 | 等待回答 | `runs/<时间>/voice_qa_results.csv` 新增行;`tts/*.wav` 落盘 |
| 6 | 播报验证 | 下行 `SPKS 24000` → PCM 帧 → `SPKE`;真机扬声器出声 |
| 7 | 可选下发 `SPKT` | 真机三音自检(440/660/880 Hz),验证播放链路 |
| 8 | 可选下发 `FILE_SEND SD:/xx.wav` | 服务器 `files_send/` 出现文件(≤8 MiB,.wav) |

> 命令行直接操作服务器:`.venv_5090_llm\Scripts\python.exe network\server\run_server.py --voice-mode real --tty`,然后在窗口输入 `MIC_START` 等文本即下发。

## 四、故障排查表

| 现象 | 原因 | 处理 |
|---|---|---|
| WSS 4401(closed abnormal) | token 不一致 | 对比 `wss.token` 与固件 `WSS_TOKEN` |
| WSS 一直重连、无"设备接入" | 证书/主机名校验失败;端口不通 | 见 1.3;`Test-NetConnection`;看固件日志 TLS 错误码 |
| MQTT 连不上 | 固件开了 TLS 而服务器 1883 明文 | 固件关 TLS;或服务器开 8883(broker.enable_tls + certs) |
| OTA 检查后 update=false | product/hw_version 不匹配;版本不高 | 对比 manifest `device` 段与固件配置 |
| OTA 下载 URL 被拒 | URL 主机名 ≠ 白名单(=server.addr) | 重跑 `make_test_artifacts.py --addr <addr>` |
| 能连但没识别 | 上行不是 16k/20ms;或 VAD 阈值(背景-60dB+25dB) | 确认音频参数;调 `voice.real.vad.background_dbfs` |
| 下行无声 | SPKS 采样率真机不支持(24000) | 改 `downlink_rate` + 固件侧一致 |
| 断线重连后不说话 | 真机断线后的上传模式 | 服务器重发 `MIC_START` 或 `MICW`;确认固件 WSS 断链自动复位行为 |

## 五、切客户服务器(验收,改动清单)

1. 固件:`CONFIG_JULIA_SERVER_ADDR` = 客户域名;token = 客户值;证书 = 客户证书(或按客户 CA 重签);
2. 服务器:同一套代码部署到客户服务器,改 `config.json`(地址/证书/token/虚拟端口);
3. 域名字段的证书:客户提供或 Let's Encrypt DNS-01 自动签发(方案文档 §2.2);
4. 走查一遍 §二 的 5 步(引擎就绪/清单/证书/端口);
5. 长稳:1 小时连续对话 + 断网/弱网演练(参考方案 §7)。
